# 委派任务说明模板（批量重写时交给子代理或协作者）

> 只有在用户同意并行处理时才委派。委派时，**把规则、示范和事实来源一并交出去**，并要求对方运行检查脚本。下面的模板可以直接复制、修改后使用。

---

你负责把【模组名】的简体中文魔导手册研究文本，改写成神秘时代 4 原版魔导手册的风格，范围包括研究标题、副标题和正文。仓库只读，不得修改任何源文件，只写你自己的结果文件。

## 必读

1. 风格技能：`<技能仓库>/SKILL.md`，以及其中要求阅读的 `references/01～09`。
2. 参考样例：使用 `<技能仓库>/examples/original/tc4-annotated.md` 的手法注释。由主 Agent 传达本次明确的资源选择，只有已启用的本体键才可查阅。停用时用现代示例工作。
3. 反例与重写示范：`<技能仓库>/examples/negative/catalog.md`、`examples/rewritten/annotated.md`。
4. 你的工作包：`【路径】/<Module>.json`，格式见 `<技能仓库>/templates/work-packet.example.json`。
5. 研究机制按当前用户提供的工作包核对。历史附属只留语言键出处，未启用的原文跳过。

## 工作包中的处理方式

- `rewrite`：必须改写并输出。
- `optional`：多为标题，确有必要才改。与单个物品强相关的标题保留。
- `keep` / `mirror`：**禁止输出**。前者是原作译文或旧版文本；后者由其他模组负责。
- `why`：给出这样处理的原因，必须阅读。

## 硬性规则（摘要，详见 SKILL.md）

1. 事实一个不丢，不发明机制，不改物品名；冲突时以现有中文为准，并报告冲突。
2. 副标题 ≠ 标题，4～10 字；不相关的研究不共用副标题。
3. 元信息改写为世界内说法，或写成括号旁白。
4. legacy 页用 `<BR>`，native 页用 `\n`；占位符和 `<IMG>` 原样保留；使用全角标点。
5. 篇幅为原文的 1.0～1.5 倍；单页约 250 字以内。
6. 开篇方式和结尾方式都要有变化；玩笑点到为止。

## 输出

用脚本生成 JSON，不要手写转义：

```json
{"module": "<Module>", "rewrites": {"<key>": "<新中文>"}, "notes": "简短说明"}
```

## 自检

```
python3 <技能仓库>/scripts/lint_zh_text.py --pairs <你生成的 pairs.json>
```

ERROR 必须为 0。WARN 中凡是“数字缺失”的，都要逐条核对。

## 汇报（不要贴全文）

1. 改写了多少个键，lint 结果如何。
2. 修改过的标题，按“旧 → 新”列出。
3. 发现的事实冲突，以及拿不准的地方。
4. 保留未处理的 WARN，以及原因。
