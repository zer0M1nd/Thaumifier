# 07 事实保真与元信息处理

> 风格重写**只能改变说法，不能改变事实**。一份读起来很美、却把冷却时间写错的手册，比一份枯燥但准确的说明书更糟。

## 1. 事实保真的硬性规则

1. **原文中的每一个事实都要保留**：数值、范围、冷却、消耗、条件、例外、按键、优先级、配置项名称、可叠加与否、是否消耗物品、失败时会怎样。
2. **不发明机制**。原文没写的效果、数值、配方，一律不写。附属原作的英文叙事中提到、但当前实现没有的能力，也不要写进去。
3. **不改物品名**。物品、方块、生物、要素的名称与项目语言文件逐字一致。
4. **冲突时以现有中文（即当前实现说明）为准**。现有中文与原作英文或旧手册冲突时，以现有中文为准，并在交付说明中报告冲突。
5. **数值可以换说法，不能换含义**。例如“消耗倍率 95%”可以写成“减耗 5%”，但不能写成“减免 95%”。“20 刻”可以写成“约 1 秒”，但最好两者都保留。
6. 可以挪动事实的位置，可以合并或拆分句子，也可以调整到相邻的页面；但同一研究的事实**总数不能变少**。

## 2. 允许删减的信息

只有以下信息可以删除，而且应当在交付说明中逐条列出：

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 纯开发信息 | “修复了原作标为 WIP 的失效反射写入”“按当前代码整理”“原作 0.12.5” | 删除，或改写成世界内说法，见第 3 节 |
| 版本出处 | “如神秘时代 6 一样”“旧英文手册写成铁钻头” | 删除，或改写成调侃：“有些旧手稿声称……你试过了……” |
| 与另一页重复的数值 | 同一研究里叙事页和补充页重复写了同一组数据 | 叙事页可以只写定性描述，数值留在补充页（原版奥术钻探机就是这样分页的） |

**不可删除**的信息：玩家需要知道才能正确使用的任何内容，包括配置开关、只能从创造模式取得、依赖哪个模组、自动化不检查研究等。这些信息要保留，只是换一种写法。

## 3. 元信息的改写方法

元信息指关于“这个模组 / 这次移植 / 这份代码”的信息，它会打破世界观。处理方式有三种，按优先级排列：

1. **改写成世界内的说法**（首选）
2. **放进段末的括号旁白**（玩家必须知道、又不好融入世界观时）
3. **删除**（纯开发信息）

### 改写对照表

| 原文（元信息） | 改写 |
| --- | --- |
| 实现说明：…… | §n补记§r<BR>……（或用一句叙事过渡） |
| 原作仅有配方与研究，没有对应的工作逻辑。本移植保留这一未完成条目，不具备攻击能力。 | 你在旧手稿中找到了这件装置的配方和研究记录，却怎么也找不到让它运转起来的方法。它就静静地立在那里，没有任何攻击能力。 |
| 原作没有生存配方的创造核心。 | 这枚核心只存在于创造之中——你从未找到在生存中制作它的方法。 |
| AT2-30r 实际代码只加载一个区块，旧说明的九区块不适用。 | （你曾以为它能看守周围九个区块。实际观察表明，它只盯得住脚下这一个。） |
| 此处修复了原作标为 WIP 的失效反射写入。 | 旧日的手稿里，这颗水晶的设想从未真正奏效；如今你补全了缺失的那一环。 |
| 以钢钻头为注魔中心。旧英文手册写成铁钻头，原作者 0.2.7 实际配方使用钢钻头。 | 叙事页写钢钻头，并加一句：“（有些旧手稿声称它用的是铁钻头。你试过了，铁钻头根本扛不住虚空的侵蚀。）” |
| 旧说明把消耗倍率与减免比例混用 | 若实际消耗为基准值的 95%，减免便是 5%。交代两者的关系。 |
| 参考版本的两种自然生成方法为空，本移植版不虚构生存配方。 | 据你所知，这两样东西并没有自然形成的途径，你也从未找到能在生存中制造它们的方法——目前它们只能从创造模式中取得。 |
| 时长按原作实际代码的 2、4、8、16 分钟四档递增 | 反复注魔之后，你发现药效的延长……是一级一级地攀升：2、4、8、16 分钟 |
| 以下保留原作的效果说明；不符合当前实现的片段划线，并紧接绿色修正。 | 以下各页抄录了你最初的效果笔记。后来的观察证明其中有些说法并不准确——你把与实际不符的句子划掉，并在旁边用绿墨写下了更正。 |
| 本版本用神秘时代 4 的空白傀儡核心替代原版发条心智。 | 你没能找到那颗传说中的发条心智，于是用神秘时代 4 的空白傀儡核心代替了它。 |
| 现代 Thermal 的旧分级元件已合并为能量单元和通量线圈。 | Thermal 那些旧的分级元件如今已合并为能量单元和通量线圈。 |
| RF 对应 Forge Energy（FE）。 | 你笔下的 RF，在如今的世界里通行的名字叫 Forge Energy（FE）。 |
| 原作 0.12.5 未给储槽、玻璃板和融合核心提供生存配方。 | （至于储槽、玻璃板和融合核心，你至今没有找到在生存中制作它们的方法。） |
| 本附属将神秘学与沉浸工程结合。 | 你翻开了工程师们的手册，惊讶地发现那些齿轮、木板与电线之间，竟藏着与神秘学相通的道理。 |
| 启用 dispenseMagicBucket 后…… | 启用 dispenseMagicBucket 配置后……（配置名保留原样） |
| 燃料和推进由服务端验证。 | （燃料消耗与推进效果由服务器校验。） |
| 服务器可禁用效果或调整部分范围与间隔。 | 保留；写在说明页末尾或括号中 |
| 完整步骤与要素见 JEI。 | 完整的步骤与所需要素，可以在配方查看器中查阅。 |
| 整合包可通过 xxx 需求定义机器配方，详见随附接口文档。 | （整合包作者可以通过 xxx 定义机器配方，详见随附的接口文档。） |

### 关于“这是框架 / 示例 / 尚未完成”

现代模组里常有“这是阶段框架，尚未指定专属法杖”“这是示例突破，不代表新增了该级法杖”之类的说明。它们是必须保留的事实，可以写成世界内的说法：

> 你感觉到，在 T6 之后，道路仍在向前延伸，只是被浓雾笼罩，看不真切。<BR>这是为 T7 阶段预留的研究框架。眼下，你只能先借一份研究笔记作为突破的入口——这一阶段专属的法杖尚未现世。

## 4. 原作译文与新文本混排

有些目标项目会在历史段落后追加现代说明。先区分来源，历史部分在技能示例内以键链接表示。

- 保留目标项目中既有译文的边界。技能仓库的示例只链接历史部分，现代追加部分可以直接对读。
- 只改写后面的现代句子，让它用同样的口吻自然接续。
- 参考不可用时，只处理有来源的现代文本与事实，在交付说明里注明未做原文对照。

## 5. 核对方法

1. **数字核对**：列出原文中的所有数字，逐一确认在新文本中仍然存在。[scripts/lint_zh_text.py](../scripts/lint_zh_text.py) 会自动报告缺失的数字。
2. **条件核对**：把原文按“如果 / 当 / 只有 / 不 / 无法 / 优先 / 除外”拆成条件清单，逐条检查。
3. **按键核对**：右击 / 左击 / 潜行 / 按住 / 空手 / 手持什么，逐一比对。
4. **否定句核对**：重写时最容易把“不会”写成“会”、把“不消耗”写丢。
5. **交叉核对**。根据用户提供的机制、现有实现和可用的本体引用核实冲突。不要把未查过的原文写进交付说明。
6. **按当前实现核对数值**。不同语言可能给出不同的减耗数字，也可能漏掉潜行时的行为。 [SCEPTRE.1](source-keys.md#k-tc.research_page.SCEPTRE.1)、[LEVITATOR.1](source-keys.md#k-tc.research_page.LEVITATOR.1)

## 6. 交付说明中应写明

- 改写了哪些键、保留了哪些键，并说明原因。
- 删掉了哪些信息，并说明原因。
- 发现了哪些事实冲突，以及你采用了哪一方。
- 修改了哪些标题，列出“旧 → 新”。
- 有哪些没有验证的地方，例如未在游戏内查看分页效果。
