# 06 格式标记与排版

> 本篇是手册文本的“语法”。写错格式不会让文字变丑，但会让游戏里显示出乱码、丢掉插图，甚至让整段文字无法解析。

## 1. 两种文本模式

TC4 系列的手册文本有两种解析方式。**动笔前必须先确认目标页面属于哪一种。**

| 模式 | 什么时候用 | 换行 | 可用标记 |
| --- | --- | --- | --- |
| **旧式（legacy）** | 1.7.10 原版与附属的 `.lang` 文本；在 TC4Revival 中，页面定义带有 `"import_legacy": true` 的 TEXT 页 | `<BR>` | `<BR>`、`<LINE>`、`<IMG>…</IMG>`、`§` 格式码 |
| **原生组件（native）** | 现代 Minecraft 文本组件；在 TC4Revival 中，未标 `import_legacy` 的 TEXT 页 | 真实换行符，在 JSON 中写作 `\n` | 只有 `§` 格式码（视渲染器而定）和 `\n`；**不能用 `<BR>`、`<LINE>`、`<IMG>`**，否则会原样显示出来 |

判断方法：找到引用这个语言键的页面定义，例如 TC4Revival 的 `data/<ns>/research_pages/*.json`，看它是否带 `"import_legacy": true`。如果原文里已经有 `<BR>`，基本可以断定是旧式；如果原文里有 `\n`，就是原生模式。

## 2. 旧式标记一览

| 标记 | 作用 | 原版用量 | 说明 |
| --- | --- | --- | --- |
| `<BR>` | 换行 | 平均每页 1.7 个 | 连续两个 `<BR><BR>` 产生一个空行。原版教学页常用空行分隔步骤。部分附属写作 `<BR/>`，两者等价 |
| `<LINE>` | 画一条分隔线 | 21 页 | 用于话题切换。前后自动断行，不必再加 `<BR>` |
| `<IMG>路径:u:v:宽:高:缩放</IMG>` | 插入图片 | 25 页 | 例如 `<IMG>myaddon:textures/gui/diagram.png:0:0:128:64:0.5</IMG>`。修改已有页面时按原样保留整段标记。 [RESEARCH.2](source-keys.md#k-tc.research_page.RESEARCH.2) |
| `§l` | 粗体 | 83 次 | 小标题、属性名、强调术语 |
| `§n` | 下划线 | 50 次 | 小标题 |
| `§o` | 斜体 | 2 次 | 引语、独白 |
| `§m` | 删除线 | 1 次 | 邪术启示录中的“涂改”效果 |
| `§5` | 紫色 | 30 次 | 标注物品、设备名 |
| `§4` | 深红 | 少量 | 标出需要玩家留意的危险。 [NODES.2](source-keys.md#k-tc.research_page.NODES.2) |
| `§6 §2 §c §3 §7 §8` | 要素色 | 少量 | 元始要素拉丁名的颜色，见 appendix-glossary |
| `§0` | 黑色（正文默认色） | | 结束颜色。原版常用 `§5……§0` 包住物品名 |
| `§r` | 重置全部格式 | | 结束粗体、下划线、斜体等。小标题写法：`§n小标题§r`、`§l§n小标题§r` |

格式码的通用规则：

- 颜色码会**清除**此前的粗体、下划线等格式，所以 `§l§5文字` 和 `§5§l文字` 的效果不同。先写颜色，再写样式。
- 每个开启的格式都要配一个结束码（`§r`，或颜色用 `§0`），否则会一直延续到段落结束，甚至跨行。
- 不要使用 `§k`（乱码）和 `§f`（白字在羊皮纸底色上看不清）。

### 小标题写法

用 `§n【步骤】§r` 标出操作小节，`§l§n【材料参数】§r` 可作为表头。旧式教学页有时插入前导空格以配合当时的字体。 [COREHARVEST.2](source-keys.md#k-tc.research_page.COREHARVEST.2)、[GOLEMSTRAW.1](source-keys.md#k-tc.research_page.GOLEMSTRAW.1)、[RESEARCH.5](source-keys.md#k-tc.research_page.RESEARCH.5)

### 属性行写法

`§l【属性甲】§r 【数值】<BR>§l【属性乙】§r 【数值】`。对照 [GOLEMSTRAW.1](source-keys.md#k-tc.research_page.GOLEMSTRAW.1)。

## 3. 原生模式要点

- 用 `\n` 换行，用 `\n\n` 产生空行。
- 不能使用 `<BR>`、`<LINE>`、`<IMG>`。需要分隔线时，用空行和小标题代替。
- 可以写成 `§n小标题§r\n` 的形式，但要确认渲染器支持 `§`；TC4Revival 支持。
- 字符示意图（结构俯视图）每行之间用 `\n`。

## 4. 占位符

- `%s`、`%d`、`%1$s`、`%2$s` 等由程序在运行时填入，可能是要素名、数值或研究名。
- **数量、编号、类型必须与原文完全一致。**可以挪动占位符在句中的位置，但不能删除、增加或改编号。
- 想写字面上的百分号时，如果该键会经过格式化处理，要写成 `%%`。拿不准时，先看原文是否已经写成 `%%`。
- 拼接型文本中，开头的 `\n\n` 等空白也是结构的一部分，必须保留。

## 5. 版面

- 原版手册正文宽 139 像素，大约一行十个汉字。
- 1.7.10 版是固定版面，原文常在句子中间断页。TC4Revival 等现代阅读器会自动分页，每个语言键是一个完整的段落，键与键之间往往还有 `page_break`。**新文本不要在句中断键。**
- 正文过长时阅读器会自动翻页，但读起来很累。参考篇幅：每个键约 100 字，最好不超过 250 字，详见 [02-structure.md](02-structure.md)。
- 插图 `<IMG>` 前后会自动断行。

## 6. 标点

| 规则 | 说明 |
| --- | --- |
| **使用全角中文标点**：，。、；：？！“”‘’（）——…… | 原版中文大量使用半角逗号和句号，这是早期翻译习惯，**不要模仿** |
| 省略号用“……”（两个“…”），破折号用“——” | 原版偶有“...”“ - ”“—”，新文本请统一 |
| 引号用“”，引号内再嵌套用‘’ | 物品名一般不加引号，可用 `§5` 或 `§l` 标注 |
| 英文专名、代码、按键前后的标点仍用全角 | 例如：“调用 getAspects() 即可。”“按 V 打开。” |
| 数字、百分号、乘号 | 数字用半角；百分号用半角“%”；尺寸用全角“×” |
| 冒号 | 中文系列名可用全角冒号，属性标签的标点依目标项目约定。 [FOCUSFROST](source-keys.md#k-tc.research_name.FOCUSFROST)、[GOLEMSTRAW.1](source-keys.md#k-tc.research_page.GOLEMSTRAW.1) |

快速自检：文本中不应出现“汉字 + 半角逗号/句号/问号 + 汉字”的组合。可用 [scripts/lint_zh_text.py](../scripts/lint_zh_text.py) 检查。

## 7. JSON 语言文件注意事项

- JSON 字符串中的换行写作 `\n`，双引号写作 `\"`。生成文件时应使用 JSON 库序列化，**不要手写转义**。
- 保留原文件的键顺序、缩进和换行风格（LF 或 CRLF），方便审阅 diff。
- `ensure_ascii=False`，直接写中文，不要写成 `\uXXXX`。
- `.lang` 文件格式是一行一个 `key=value`，值中不能有真实换行；换行一律用 `<BR>`。
