# 04 页面类型与模板

> 每种页型介绍用途、骨架和注意事项。旧文用语言键链接定位，现代范例来自 TC4Revival 的重写。骨架里的【】是待填内容，示例中的具体数值属于各自模组。

---

## A. 物件描述页（原版约 50% 的首页）

**用途**：介绍一件物品、方块或设备是什么、有何性质、能做什么。

**骨架**

```
这种【物品】【生动的定义 / 材料的魔法性质】。<BR>
它能够【功能 1】，【功能 2 + 数值】。<BR>
【补充：限制 / 与同类比较 / 使用感受】。
```

**原版范例**

[NITOR.1](source-keys.md#k-tc.research_page.NITOR.1)

[ROD_silverwood.1](source-keys.md#k-tc.research_page.ROD_silverwood.1)

[LEVITATOR.1](source-keys.md#k-tc.research_page.LEVITATOR.1)

**注意**

- 定义可以从材料、外观或产生作用的原因写起。 [NITOR.1](source-keys.md#k-tc.research_page.NITOR.1)、[CAP_gold.1](source-keys.md#k-tc.research_page.CAP_gold.1)、[ROD_silverwood.1](source-keys.md#k-tc.research_page.ROD_silverwood.1)
- 一句话的物件页是允许的，前提是这句话本身有内容、有判断。

## B. 发现叙事页（原版约 25%）

**用途**：讲研究的来由，特别适合承接前置研究、需要交代“为什么能做到”的条目。

**骨架**

```
【前置经历 / 遇到的麻烦 / 一次观察】。<BR>
你【发现 / 意识到 / 研究出】【原理】，于是【造出 / 掌握了】【物品或能力】。<BR>
【它能做什么 + 数值】。<BR>
【局限 / 代价 / 展望】。
```

**原版范例**

[WANDPEDFOC.1](source-keys.md#k-tc.research_page.WANDPEDFOC.1)

**现代范例**（神秘万象·通用晶簇化）

> 你在晶簇化研究中学会了提纯铁、金、铜等寻常矿石。可这个世界上的矿石远不止这些。<BR>秩序源质能从任何矿石中提取出有价值的部分。这项工艺会读取其他模组的矿石标签：每个矿石方块产出两个矿簇，粗矿产出一个矿簇。矿簇可以冶炼出原本两倍的产物。<BR>格雷科技的材料使用矿簇形态，还可以粉碎为粗矿粉碎产物的 1.5 倍。配方查看器中会列出当前世界可用的材料。

**注意**

- “来由”要具体，最好点名前置研究或玩家的经历。“经过无数个小时的研究”这种空话少用。
- 不要每页都用“你发现”开头。可以换成“你注意到”“你一直怀疑”“得益于”“研究……的过程中”。

## C. 说明 / 世界观页

**用途**：讲基础概念（灵气、要素、扭曲、外域）或宏观设定。

**骨架**

```
【现象】是【定义】。【来源未明 / 众说纷纭】，【研究者倾向的解释】。<BR>
【它如何影响神秘使】。<LINE>
【重要警示（可用 §4 红色）】。
```

**原版范例**

[NODES.1](source-keys.md#k-tc.research_page.NODES.1)

[NODES.2](source-keys.md#k-tc.research_page.NODES.2)

**注意**。为尚无定论的现象保留几种解释。 [NODES.1](source-keys.md#k-tc.research_page.NODES.1)

## D. 教学 / 操作页

**用途**：讲多步骤的操作，例如研究流程、搭建注魔祭坛、使用界面功能。

**骨架**

```
§n【步骤名】§r<BR>
【为什么要这样做（一句）】。<BR>
只需【操作】，就能【结果】。【进一步操作】时，【结果】。<BR>
注意：【容易出错的地方】。
```

**原版范例**

[ARCTABLE.1](source-keys.md#k-tc.research_page.ARCTABLE.1)

**现代范例**（本体·要素关联，界面功能说明）

> 缸中之脑整天在罐子里嘟囔个不停。你本以为那不过是些无意义的呓语，直到某天你注意到，它念叨的要素名称总是成群结队地出现——每一种要素都与另外几种要素有着千丝万缕的联系，就像一本家谱里的亲族。<BR>你把这些关系整理成了一张谱系图。如今只需用中键点击某个要素，或在搜索框中输入“~”再加上要素的名称，就能查出所有与它直接相连的要素——当然，也包括它自己。<BR>中键要在松开时才算一次点击，因此拖动时并不会顺手触发搜索。<LINE>至于怎样让这些联系自己连成一条完整的路径，你觉得还需要更深入的研究。

**注意**：界面操作也可以写进世界观，比如“你养成了……的习惯”“你把……整理成了……”。按键必须写准确。

## E. 属性表页

**用途**：给出同类物品可比较的数值（傀儡材质、法杖容量）。

**骨架**

```
【一两句描述或比较】。<BR>
§l§n【名称】属性§r<BR>
§l【属性 1】:§r 【值】<BR>
§l【属性 2】:§r 【值】<BR>……
```

**原版范例**

[GOLEMSTONE.1](source-keys.md#k-tc.research_page.GOLEMSTONE.1)

**注意**。属性可以是相对等级或具体数字。表前加一两句材料描述，读者才能理解这些数值的意义。 [GOLEMSTONE.1](source-keys.md#k-tc.research_page.GOLEMSTONE.1)

## F. 解锁 / 隐藏页

**用途**：完成另一项研究后才显示的补充用法，例如升级、联动或进阶技巧。

**骨架**

```
§n【某升级 / 某研究】解锁§r【可选 IMG 图标】
【装有它的 X 现在还能……】。【条件或失败情形】。
```

**原版范例**

[COREFISHING.3](source-keys.md#k-tc.research_page.COREFISHING.3)

[ARCANELAMP.2](source-keys.md#k-tc.research_page.ARCANELAMP.2)

## G. 结构搭建页（多方块）

**用途**：说明多方块结构如何摆放。现代模组中很常见，原版只有零星几处（注魔祭坛、炼狱熔炉）。

**骨架**

```
§n【搭建 X】§r<BR>
【一句来由或比喻】。<BR>
【逐层 / 逐部件的摆放说明，含尺寸、材料、相对位置】。<BR>
【可选：字符示意图，每行一个 <BR>】<BR>
【启动方式与消耗】。【保持畅通 / 加载等条件】。
```

**现代范例**（自动化魔法·下界之脑）

> §n构筑下界之脑§r<BR>下界的脑子总得有个合适的颅骨来装。按照下面的俯视图摆放（N 为下界之脑，R 为符文，点为空气）：<BR>...R...<BR>...R...<BR>..RRR..<BR>RRRNRRR<BR>..RRR..<BR>...R...<BR>...R...<BR>四条臂的末端各向下再添一个符文，共需 20 个符文。下方的空间要保持畅通。<BR>用含有 75 点火与 25 点秩序魔力的法杖将其启动，并从控制器上方持续供应火厘魔力。

**注意**

- 尺寸用“3×3”（全角乘号）或“3x3”。同一文本内保持一致。
- 字符示意图必须**逐字保留**，每行之间用 `<BR>`。非 legacy 页面用 `\n`。
- 来由或比喻一句即可，不要喧宾夺主。

## H. 补记页（追加在旧研究之后的现代说明）

**用途**：原作研究的正文从外部加载、不能改动，移植版需要在后面追加机制说明。也用于把“实现说明”改写为世界内的文本。

**骨架**

```
§n补记§r<BR>        ← 或 §n补记：【主题】§r，或用一句叙事过渡代替
【机制 + 数值】。<BR>
【条件 / 例外】。<BR>
【可选：一句收尾】。
```

**现代范例**（高等神秘学·节点修改器）

> §n补记§r<BR>处理时，修改器先每秒吸入 1 点源质，再每 10 秒消耗 1 份精华。增添一种要素需要四份相同的精华，节点最多拥有六种要素；提高容量只会让第一种要素提升 1 点。<BR>中途若换走或改变目标节点，处理便会中止，已经消耗的材料也不会返还——节点可不会感谢半途而废的医生。

**注意**

- 先确定这一研究的叙述口吻。启用的本体引用可以帮助校准，附属可看[声音画像](08-addon-voices.md)及其现代改写。
- 同一模组里大量补记页都以“§n补记§r”开头会显得机械。可以轮换使用主题小标题（“§n召唤代价§r”“§n调教味蕾§r”）或一句叙事过渡。

## I. 使用方式页（简明操作页）

**用途**：失落遗物学等模组为每件遗物单独配了一页“使用方式”，把操作和数值集中写清楚。

**骨架**

```
§n使用方式§r<BR>
【佩戴位置 / 持有方式】时，【效果 + 数值】。【操作】可【效果】。【叠加 / 冷却 / 限制】。
```

**反例 → 现代范例**（失落遗物学·采掘护符）

- 反例：`使用方式<BR/>戒指：挖掘速度 +100%，方块触及 +2。相同类型不叠加。`
- 改写：`§n使用方式§r<BR>作为戒指佩戴时，挖掘速度提升 100%，方块触及距离增加 2 格。同类护符佩戴多枚并不会叠加。`

**注意**：这类页面以清晰为先，叙事成分可以很少，但必须是完整的句子，不能写成电报体或冒号清单。

---

## J. 消耗表 / 数据页

**用途**：列出召唤、仪式、配方的要素消耗，或繁殖概率等数据。

**骨架**

```
§n【主题】§r<BR>
【一句引导】<BR>
【项目】：【数据】。<BR>
【项目】：【数据】。<BR>
（【数据前提，如“以上为默认消耗”】。）
```

**现代范例**（自动化魔法·僵尸猪人符文）

> §n召唤代价§r<BR>下界之脑每次召唤消耗：Corpus 2, Ignis 2。<BR>维度诱饵每 15 次召唤消耗：Fames 15, Cognitio 9, Lucrum 3。<BR>（以上为默认消耗，要素以拉丁名标注。）

**注意**：数据页可以保留列表形式，但数据前提（默认值、可配置等）应改成括号旁白。数据量极大时（如蜜蜂繁殖谱系），按主题拆页，每页配一个小标题（“§n元素之蜂§r”“§n节点之蜂§r”）。

## K. 邪术 / 禁忌页

**用途**：腐化、扭曲、外域、血腥教团、饮用危险物质等。

**骨架**

```
【一句不安的开场：低语 / 梦境 / 违背常理的触感】。<BR>
【你知道了什么 / 能做什么，机制照写】。<LINE>
【代价：扭曲、生命、理智】。<BR>
【一句自我合理化或不祥的余韵】。
```

**原版范例**

[VOIDMETAL.1](source-keys.md#k-tc.research_page.VOIDMETAL.1)

**现代范例**（神秘基础学·初探污染）

> 低语从未停止。它们告诉你，腐化并不只是需要清除的污秽——它也可以被饮下。<BR>你如今知道了饮用§5凝聚腐化§0的方法。只有在生命值全满时，你的身体才承受得住这一仪式；若是负伤时饮下，必死无疑。即便满血，你也会只剩半颗心，并在之后一段时间里饱受严重的负面效果折磨。<LINE>但低语仍在呼唤你继续深入。在下界 Y 不高于 6 的深处饮下它，仪式便会向前推进——你的扭曲也会随之加深。<BR>你不确定这是否是个好主意。你只确定自己已经停不下来了。

**注意**：恐怖来自轻描淡写和合理化，而不是血腥描写。数值与条件照写不误。

## L. 联动页（跨模组）

**用途**：神秘学设备与其他模组的结合，例如机械动力、AE2、格雷科技、林业、植物魔法、血魔法。

**骨架**

```
【神秘使眼中的对方流派：“机械师们的……”“格雷科技的工程师们……”】。<BR>
【你如何用神秘学改造或借用它】。<BR>
【机制 + 数值，对方模组的术语沿用该模组的中文译名】。<BR>
【可选：两个流派之间的调侃】。
```

**原版附属范例**（神秘能源原作）

[thaumicenergistics.research_page.TERESEARCH.1](source-keys.md#addon-ThaumicEnergistics-thaumicenergistics.research_page.TERESEARCH.1)

**现代范例**（神秘万象·奥术马达，节选）

> 机械师们的齿轮与传动轴总让你觉得有些笨拙——它们离不开水车、风车，或是一大堆熊熊燃烧的燃料。直到某天你意识到，节点中继器里流淌的厘魔同样能推动这些齿轮。<BR>即便无人照看，奥术马达也会缓缓转动，提供 256 su 的应力与 16 rpm 的转速。……

**注意**

- 其他模组的名称可以直接写，比如“机械动力”“格雷科技”“植物魔法”。原版附属也这样写，例如 Ars Magica 的 AM 魔力、BuildCraft。
- 对方的术语（su、rpm、EU、FE、LP、mB）照抄，不要硬译。
- 界面名“JEI”写作“配方查看器”。

## M. 系列短页

**用途**：大量平行、简单的条目，例如嬗变配方、植物转化、蜂框精华。

**原版范例**

[TRANSIRON.1](source-keys.md#k-tc.research_page.TRANSIRON.1)

**现代范例**（神秘时代：未来·水银花转化）

> 没有银树的荫庇，水银花便无处生长——除非你亲手把它变出来。<BR>在坩埚中，你可以把虞美人转化为水银花。

**注意**：真正平行时，可以共用骨架，但最好每条给一句**专属的引子**。原版嬗变系列完全同句，这是允许的；现代重写时加一句引子能让系列更耐读。

## N. 元信息旁白

**用途**：玩家必须知道、但不属于世界观的信息，例如配置开关、只能在创造模式取得、依赖某个模组、配方由整合包决定、数值可配置。

**写法**：放在段末，用一句完整的**括号旁白**。

| 信息 | 旁白示例 |
| --- | --- |
| 配置开关 | （服务器可在配置中关闭此功能。）（只有在模组配置中启用 breadWand 后，才能研究和制作。） |
| 仅创造模式 | （此物目前只能在创造模式中取得。）也可以写成世界内说法：“你从未找到在生存中制作它的方法。” |
| 依赖模组 | （需要安装 Thermal。）或写进句子：“安装了 Thermal 时，……” |
| 默认值 | （以上为默认消耗。）（数值为默认设置，服务器可调整。） |
| 整合包接口 | （整合包作者可以通过 xxx 定义配方，详见随附的接口文档。） |
| 配方以界面为准 | 配方见配方查看器。 |

神秘工匠曾把取得条件放进段末括号。 [ttresearch.page.SHARE_TOME.0](source-keys.md#addon-ThaumicTinkerer-ttresearch.page.SHARE_TOME.0)

## O. 拼接片段（由代码组合的文本）

**用途**：部分模组会把多个语言键拼接成一页，例如“效果描述 + `\n\n使用细节：` + 细节”；也会用 `%s`、`%1$s` 插入要素名。

**规则**

- 前导的 `\n\n` 等空白必须保留，标签可以换成更有味道的说法（如“使用细节：”改为“实测笔记：”）。
- 占位符的数量和编号必须与原文完全一致。
- 被拼接的片段要能接上前文，语气保持一致。例如原作的俏皮描述后面，接研究者精确、简洁的观察记录。

**现代范例**（神秘注魔·Tempestas 效果细节，接在原作描述之后）

> 只有在雷暴天气、且方块上方能看见天空时，它才会每 50 刻以 1/50 的概率在方块上方召下一道真正的闪电。普通的降雨可唤不来雷霆。
