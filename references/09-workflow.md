# 09 工作流程与自检

## 1. 三种任务

| 任务 | 输入 | 关键步骤 |
| --- | --- | --- |
| **A. 从零撰写**新研究文本 | 机制说明、配方、前置研究 | 定位分类与语气 → 选页型 → 写正文 → 拟副标题 → 自检 |
| **B. 风格重写**已有的功能性文本 | 现有中文（事实来源）、可能有原作英文 | 盘点范围 → 提取事实清单 → 重写 → 逐条核对事实 → 自检 |
| **C. 翻译**原作英文 | 英文原文 | 理解原作语气 → 意译（副标题本地化）→ 术语对齐 → 自检 |

## 2. 任务 A：从零撰写

1. **收集事实**：功能、数值、操作、条件、配方、前置研究、与哪些模组联动。写成要点清单，这就是“事实清单”。
2. **确定位置**：它属于哪个研究分类（决定语气，见 01 §3）？前置研究是什么（决定“来由”）？
3. **选择页型**：物件描述、发现叙事、说明、教学、属性表、结构搭建等，见 [04-page-patterns.md](04-page-patterns.md)。事实多时，规划成多页：首页叙事，后续补充。
4. **写正文**：按四拍结构“引子 → 原理 → 用法与数值 → 余韵”写，内容少就写短。
5. **拟副标题**：按 [03-titles-subtitles.md](03-titles-subtitles.md) 的步骤，4～10 字。
6. **标题**：物品名，或“前缀：项目”。
7. **自检**：见第 6 节，并运行 `scripts/lint_zh_text.py`。

## 3. 任务 B：风格重写（批量）

在 TC4Revival 中处理约 600 个键的经验做法：

1. **盘点范围**
   - 找出所有研究定义（研究目录与研究页 JSON），列出每页引用的语言键。
   - 区分哪些键**在工作区语言文件中**（需要重写），哪些是**运行时从原作外部加载的**（不改）。
   - 识别不应改动的键：原作忠实译文、错别字修正补丁、差异提示和纠错数据、界面文本。
   - 识别**跨模组共享键**：同一个键出现在两个模组的语言文件中时，指定一个负责方，另一方镜像同步。
   - 识别**代码动态引用的键**：例如逐项附魔研究的副标题由 Mixin 动态拼出。在源码中搜索键名前缀。
2. **为每个模组生成工作包**：每个键的当前中文、英文（若有）、页面模式（legacy 或 native）、处理方式（重写 / 可选 / 保留 / 镜像）和原因。见 [templates/work-packet.example.json](../templates/work-packet.example.json)。
3. **找同类样例**。使用附属声音画像和现代同页型案例。启用了本体资源时，可再按键查询相近的历史页面。
4. **用脚本输出结果**：每个模组一个 `{key: 新文本}` 的 JSON，用 JSON 库序列化，**不要手写转义**。
5. **逐模组校验**：运行 lint 脚本，确保 ERROR 为 0，WARN 逐条查看。
6. **组装**：把新值写回原语言文件的副本，保持键顺序、缩进和换行风格；比对新旧文件，确认只有目标键变化。
7. **生成对照表**：逐键列出“改写前 / 改写后”，方便人工审阅。
8. **交付说明**：范围、规模、删减项、冲突、标题变更、未验证项，见 [07-facts-and-meta.md](07-facts-and-meta.md) §6。

**关于并行**：交给多个子代理并行重写确实快，但它们会各写各的，风格容易漂移，还会消耗大量资源。项目方可能并不希望并行。除非用户明确同意，否则建议单线程逐模组完成；需要委派时，用 [templates/rewrite-task-brief.md](../templates/rewrite-task-brief.md) 写清规则，并附上示范。

## 4. 任务 C：翻译原作

1. 确定可用来源与文本语气。停用资源时跳过历史引用；任务以旧文为必要输入时，标明缺少原文，继续能独立完成的部分。
2. **正文**。较长的英文复句可以拆成中文短句。用段落重点决定从何起笔，避免反复使用相同动词。
3. **副标题**：本地化，见 03 §2.5。
4. **术语**。先与项目中的物品名对齐。已启用本体资源时，可以补查[术语索引](appendix-glossary.md)。
5. 原作中与当前实现不符的部分，按 07 处理：保留原意，必要时加注。TC4Revival 采用的是“删除线 + 绿色更正”的追加替换机制，不要直接改写原意。

## 5. 常见错误（来自实际重写经验）

| 编号 | 错误 | 表现 | 修正 |
| --- | --- | --- | --- |
| E1 | 说明书腔 | “右键打开界面，放入物品后点击按钮即可。” | 加入说话者：来由、判断、效果 |
| E2 | 参数堆砌 | 一段里塞了十个数值和分号 | 用“首先 / 其次”或分段；必要时拆页 |
| E3 | 元信息 | “实现说明”“原作代码”“本移植版”“JEI” | 见 07 §3 |
| E4 | 副标题 = 标题 | 标题“奥术马达”，副标题也是“奥术马达” | 重新拟写 |
| E5 | 泛化共用副标题 | 35 个遗物都是“失落的知识，重现的遗物” | 每个研究写自己的副标题；只有平行系列可以共用骨架 |
| E6 | 半角标点 | “消耗2点,产出3个.” | 改为全角标点 |
| E7 | `<BR>` 用在非 legacy 页 | 原生组件页中出现 `<BR>`，会原样显示 | 改为 `\n` |
| E8 | 丢事实 | 漏掉冷却、例外、否定条件 | 用事实清单逐条核对；lint 会报告缺失的数字 |
| E9 | 发明机制 | 照着原作英文写了当前实现没有的能力 | 以现有中文为准 |
| E10 | 改物品名 | 同一物品在相邻两页出现两个名称 | 与目标语言键逐字对齐。历史例见 [tile.blockChestHungry.name](source-keys.md#k-tile.blockChestHungry.name) |
| E11 | 套路疲劳 | 每页都以“你发现”或“§n补记§r”开头，或每页都以玩笑收尾 | 混用四种开篇；玩笑不超过三分之一 |
| E12 | 注水 | 为了“有风格”把 60 字写成 300 字 | 以原文 1.0～1.5 倍为宜；原版中位数约 100 字 |
| E13 | 太薄 | “将虞美人转化为水银花。” | 至少补一句来由或判断 |
| E14 | 冷门梗 / 过时梗 | 小众 ACG 梗、粗俗网络口语 | 用自嘲、反转、轻描淡写等不依赖时效的幽默 |
| E15 | 冗余重复 | “专属的法杖尚未现世，相应的法杖也还没有指定” | 写完读一遍，删去同义反复 |
| E16 | 占位符损坏 | 删掉了 `%1$s`，或改了编号 | 数量与编号与原文一致 |
| E17 | 删掉 IMG | 改写时漏了 `<IMG>…</IMG>` | 原样保留 |
| E18 | 句中断键 | 模仿 1.7.10 的固定版面，在句中断开到下一个键 | 每个键都是完整的段落 |
| E19 | 教读者 | “请您注意……”“建议玩家……” | “注意：”“务必……”，主语用“你” |
| E20 | 共享键不同步 | 两个模组中同一键的文本不同 | 指定负责方，另一方镜像 |

## 6. 自检清单

### 内容

- [ ] 事实清单中的每一项都在新文本中，数值、条件、否定、例外都在。
- [ ] 没有发明机制；物品名与语言文件一致。
- [ ] 元信息已改写、移入括号旁白或删除，删除的已记录。

### 风格

- [ ] 有说话者：来由、判断或情绪至少有一项，属性表、使用方式页除外。
- [ ] 语气与研究分类相称。邪术类不搞笑，傀儡类可以宠溺吐槽。
- [ ] 开篇方式在相邻条目间有变化。
- [ ] 玩笑点到为止，不超过三分之一的页面。
- [ ] 篇幅：单键约 60～250 字；超过 250 字时考虑拆页。

### 标题与副标题

- [ ] 标题与物品名一致，或使用“前缀：项目”格式；没有标记和元信息。
- [ ] 副标题 ≠ 标题，4～10 字，最长不超过 15 字，不加句号。
- [ ] 不相关的研究没有共用副标题。

### 格式

- [ ] 页面模式正确：legacy 页用 `<BR>`，native 页用 `\n`。
- [ ] 占位符数量与编号一致；已有的 `<IMG>` 全部保留。
- [ ] 每个格式码都有对应的 `§r` 或 `§0` 结束。
- [ ] 全角中文标点，“汉字 + 半角标点 + 汉字”的组合为零。
- [ ] JSON 合法，用库序列化，`ensure_ascii=False`。

### 交付

- [ ] 运行 `scripts/lint_zh_text.py`，ERROR 为 0。
- [ ] 新旧文件只有目标键发生变化。
- [ ] 已附对照表与交付说明。

## 7. 让文本“更像”的小技巧

1. **把操作写成习惯或技巧**：“你养成了……的习惯”“如今只需……”“你发现，只要……”。
2. **给数值一个意义**。可以对照一件已知设备的需求量，但要先核实两者单位和条件。原版容量比较见 [ROD_greatwood.1](source-keys.md#k-tc.research_page.ROD_greatwood.1)。
3. **找一个感官细节**。例如材料冷暖如何，或装置工作前后的声音有什么变化。 [VOIDMETAL.1](source-keys.md#k-tc.research_page.VOIDMETAL.1)
4. **承认局限**：“它还不够完美”“你确信还有改进的余地”。这正是 TC4 的未完成感。
5. **用“首先 / 其次 / 最后”列特性**，比分号清单自然。
6. **结尾留一个钩子**：“这或许是一门全新学科的开端”“你开始怀疑，养蜂这件事是不是已经有点失控了”。但不要每页都留。
7. **写完大声读一遍**：拗口的长句、重复的词、电报体，读出来会一目了然。
